## Quality Risk Matrix (For Bishop QA)

### Critical Blockers (Must-Test)

| Risk | Mitigation | Test Case |
|------|-----------|-----------|
| Decision race condition | Backend rejects second ResolvePendingDecision with HubException | Two clients submit simultaneously; expect 1 success, 1 error |
| Forced target bypass | Backend validates forcedTargetPlayerIdForNextTurn; frontend disables invalid targets | Red wire triggers; attempt cut on non-forced player; expect error |
| Empty hand reveal | Backend checks targetPlayer.HasCards() before processing | Reveal all 4 cards from one player; attempt 5th; expect error |
| Outcome corruption | Backend sets both Winner and Reason when game ends | Play to bomb explosion; verify Winner=Moriarty, Reason=BombExploded |
| Round prep hang | Backend checks all players ready before advancing | 3/4 ready; verify stuck. 4th marks ready; verify advances |

### High-Risk Concerns

1. **State sync lag:** Frontend receives stale state after rapid actions  
   → Mitigation: Backend always broadcasts full LobbyStateDto

2. **Null effect handling:** RevealedWire.effect is null; frontend crashes  
   → Mitigation: effect is optional; frontend handles gracefully

3. **Active player invalid:** activePlayerId doesn't exist in players (e.g., player left mid-turn)  
   → Mitigation: Backend ensures GetActivePlayerId() returns valid ID after player leaves

4. **Bomb color mismatch (Evolution):** Backend tracks different colors than frontend  
   → Mitigation: SelectedBombColors sent in rules; match player count

5. **Mobile animation backlog:** SignalR events arrive faster than frontend can render  
   → Mitigation: Frontend implements event queue, debounce, 60fps cap
