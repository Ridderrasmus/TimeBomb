## Acceptance Criteria Matrix

### Feature: Game State Visualization (Phase 1)
- [ ] Turn Banner: Displays "YOUR TURN" or "Waiting for X" based on activePlayerId
- [ ] Active Player Highlight: isActiveTurnPlayer rendered with CSS style
- [ ] Wire History: revealedWires in reverse order, scrollable
- [ ] Player Status: Remaining wire count updates after each reveal
- [ ] Game Phase: "Round Preparation" vs "Active Turn Play" rendered correctly

### Feature: Decision Flow (Phase 2)
- [ ] Pending Decision Modal: Displays when pendingDecision exists
- [ ] Color Picker: availableColors rendered as buttons, unclickable colors disabled
- [ ] Permission: Only requestedByPlayerId can submit; others see "Waiting..."
- [ ] Resolution: User click → ResolvePendingDecision hub → modal clears → game continues
- [ ] Error Handling: Invalid colors rejected with error message; retry enabled

### Feature: Forced Target & Turn Constraints (Phase 2)
- [ ] Display: "Forced target: [name]" shown when forcedTargetPlayerIdForNextTurn set
- [ ] Filtering: Cut buttons render only for forced target; others disabled
- [ ] Error: Invalid target → hub error → error message displayed

### Feature: Responsive (Phase 1–3)
- [ ] Desktop 1920×1080: No scroll, text readable, all panels visible
- [ ] Tablet 768×1024: Vertical stack, ≥48px touch targets, scrollable panels
- [ ] Mobile 375×667: Single column, full-width inputs, sticky turn banner

### Feature: Accessibility (Phase 3)
- [ ] Keyboard: Tab order logical, Enter activates, Arrows on dropdowns
- [ ] Focus: :focus-visible ring (≥2px, ≥4.5:1 contrast)
- [ ] Semantic HTML: `<button>`, `<label for>`, `role="alert"`, `role="button"`
- [ ] Contrast: ≥4.5:1 text vs background (WCAG AA)
- [ ] Screen Reader: Turn banner changes announced, errors read immediately
- [ ] Motion: prefers-reduced-motion respected (no animations)
